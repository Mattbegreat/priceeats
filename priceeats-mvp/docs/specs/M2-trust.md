# M2 信任感

## 背景
11/16 實測：南港車站 100 元 766 筆中 695 筆標「舊資料」（91%）；正式資料沒有評分卻顯示評分篩選與「評價最高」排序；店名含雜訊；網頁描述寫「測試資料示範版」。

## 要做
1. 新鮮度分級（src/lib/pricing/）：正式模式改為 6 個月內「近期」、6–12 個月「可能需要確認」、超過 12 個月「舊資料」。測試資料模式維持 30／90 天。
2. 正式模式（IS_REAL_DATA）隱藏結果頁「最低評分」篩選與「評價最高」排序；URL 帶 minRating 或 sort=rating 時忽略。
3. meta description：正式模式不出現「測試資料示範版」。改「輸入預算，找附近買得起的餐點與店內價。」
4. 店名清理（scripts/build_from_ocr.py 的 clean_name）：移除括號內促銷字、「連鎖第一品牌」「心累」「見紅休」等尾綴；先用 scripts 列出受影響店名清單到 data/name-clean-preview.md，不直接寫 DB。
5. 餐點頁：來源是菜單照片辨識但沒有圖時，不顯示「尚無菜單照片」，改「菜單照片未公開」。

## 不能碰
- 不改 migration、不寫 Supabase 資料（店名實際更新另案，需 Matt 同意）。
- 不新增套件。

## 驗收
- `npm run typecheck && npm run lint && npm test && npm run test:e2e` 全過，新增測試涵蓋 1、2、3。
- 線上：南港車站 100 元 500m「舊資料」比例 < 30%（用程式數，不目測）。
- 結果頁 DOM 無「最低評分」「評價最高」。

## 停止條件
同一錯誤修 3 次失敗就停，回報。
